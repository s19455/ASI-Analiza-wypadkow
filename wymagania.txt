Wymagania projektu zaliczeniowego 
1. Organizacja projektu i zespołu 
• Projekt realizowany w zespole
• Repozytorium kodu (np. GitHub/GitLab) z historią zmian
• Ustalone środowisko pracy:
◦ Python
2. Wersja podstawowa modelu (baseline) 
• Wybór problemu ML (klasyfikacja/regresja/analiza danych)
• Implementacja rozwiązania w Jupyter Notebook
• Notebook zawiera:
◦ eksplorację danych (EDA)
◦ preprocessing
◦ trening modelu bazowego
◦ ewaluację

• Notebook udostępniony online (np. GitHub, Kaggle, Colab)
3. Struktura projektu i pipeline 
• Refaktoryzacja kodu:
◦ podział na moduły Python (src/, data/, models/, notebooks/)
• Implementacja pipeline’u ML z użyciem:
◦ Kedro (lub alternatyw)
• Pipeline obejmuje:
◦ pobieranie danych
◦ preprocessing
◦ trening
◦ ewaluację

4. Udoskonalanie modelu 
• Implementacja systemu śledzenia eksperymentów:
◦ np. MLflow / Weights & Biases
• Wykorzystanie AutoML:
◦ np. Autogluon, TPOT, PyCaret
• Inżynieria cech:
◦ selekcja cech
◦ transformacje
• Strojenie hiperparametrów:
◦ Grid Search / Random Search / Bayesian Optimization
• Porównanie kilku modeli
5. Pipeline produkcyjny 
• Pipeline trenowania i inferencji wdrożony na wybranej infrastrukturze:
◦ lokalnie / Docker / chmura (np. AWS, GCP, Azure)
• Udostępnienie modelu:
◦ API (np. FastAPI / Flask)
• Monitoring:
◦ logowanie predykcji
◦ wykrywanie driftu danych
• Optymalizacja:
◦ wybór architektury (np. batch vs real-time)
◦ optymalizacja czasu i zasobów
6. MLOps / Repozytoria 
Do wyboru jedna z dwóch ścieżek:
Opcja A – Repozytoria 
• Wersjonowanie danych (np. DVC)
• Repozytorium cech (Feature Store, np. Feast)
• Repozytorium modeli (np. MLflow Model Registry)
Opcja B – Automatyzacja MLOps 
• CI (Continuous Integration):
◦ testy, linting (np. GitHub Actions)
• CD (Continuous Deployment):
◦ automatyczne wdrożenia
• Continuous Training:
◦ automatyczne ponowne trenowanie modelu
7. Dokumentacja 
• Kompleksowa dokumentacja projektu:
◦ opis problemu
◦ opis danych
◦ architektura systemu
◦ sposób uruchomienia
• Wizualizacja architektury:
◦ diagram (np. draw.io)
• README w repozytorium
8. Podsumowanie i prezentacja 
• Prezentacja końcowa (10–15 min):
◦ problem i rozwiązanie
◦ pipeline ML
◦ wyniki
◦ wdrożenie
• Demo działania projektu (np. API lub notebook)
